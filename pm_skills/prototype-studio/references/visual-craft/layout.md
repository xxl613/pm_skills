# 布局、信息层级与密度

融合 impeccable layout/product 与 huashu-design 容量方法。布局必须服从任务与内容，不能由风格标签决定。

## 选择结构

| 任务 | 优先结构 | 观察点 |
|---|---|---|
| 比较大量同类对象 | 表格/可筛选列表 | 同列对齐、关键列优先、操作可发现、空筛选与分页 |
| 阅读和处理一个对象 | 主详情 + 次要信息/操作 | 标题、状态、主要动作清楚；长内容滚动独立合理 |
| 编辑复杂对象 | 分组表单/分步流程 | 相关字段相近、说明随字段、保存与取消路径 |
| 连续AI任务 | 对话基座 + 结果卡/工具面板 | 输入始终可达、过程与最终结果分明、工具不挤坏阅读列 |
| 多维工作台 | 稳定区域/列网格 | 区域优先级清晰、数据有用途、不堆装饰指标 |

## 空间是信息

- 同组元素的间距小于跨组间距，形成自然阅读层次。选定有限间距刻度并在项目持续使用；4/8的倍数是起点，不覆盖已有标准。
- 对齐同类标题、数值、元信息、操作行的基线。视觉上确实偏移时做局部光学校正，不能以“精修”为理由随意改标准件几何。
- 字号、字重、空间、位置共同表达主次。先减少多余的容器和边界，只有必要时才增加颜色/尺寸对比。
- 密集页面可以有表格和重复行；重复业务需要稳定结构。展示页才通过不同章节布局形成叙事节奏。
- 卡片适合独立可操作对象，分隔线/留白适合一组连续内容。嵌套容器须表达真实父子关系，不以“永远禁卡片”代替判断。

## 实现

Flex处理一维行/列；Grid处理需要行列同时对齐的区域。复杂页面可用命名grid-area，组件自身变化可用container query。重排不能让视觉顺序与键盘/读屏顺序冲突。

建立顶栏、下拉、遮罩、弹窗、toast等语义层级。弹出内容被overflow裁剪时使用正确的顶层/portal/popover，而不是不断放大z-index。固定栏预留内容空间；允许应当滚动的内容滚动。

## 看图检查

缩小或模糊截图仍应辨认主任务、主要信息和分组。检查页面是否拥挤或空旷、主要操作是否可达、同级区域是否对齐、真实长内容是否改变布局。不要用overflow:hidden掩盖溢出。
