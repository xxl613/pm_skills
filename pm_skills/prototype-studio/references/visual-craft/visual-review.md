# 视觉与操作验收

以真实浏览器渲染为证据。代码检查、构建、截图和点击分别记录，不相互替代。

| 维度 | 看什么 | 失败例 |
|---|---|---|
| 层级 | 首要任务、主内容、主动作一眼可辨 | 十个同色同重卡片，没有优先级 |
| 空间 | 组内/组间节奏、网格与基线、内容容量 | 文案靠缩小字号塞入；底部输入挡列表 |
| 排印 | 中文混排、长文、数字列、标签可读 | 灰色小字、无意义断行、单元格文字挤出 |
| 一致 | 同类对象/控件/状态/角色跨页一致 | 同一Agent换头像；保存按钮每页不同 |
| 资产 | 真实资源、比例、mask、深浅底可见 | 临时图URL、白色mask当普通图片 |
| 操作 | 真入口、输入、提交、取消、恢复 | 点什么都toast，列表变了统计没变 |
| 端与无障碍 | 小屏、键盘、触控、焦点与减少动效 | hover-only关键入口；模态外仍可点击 |

代表页校准后检查跨页共有区域。对标准件用指定基准核对，不因更“新潮”变更类名、素材、间距或交互。改过业务逻辑的页面，旧的“用户已审核”不能自动作为本次通过证据。

交付前按真实风险选择关键路径：新增对象→列表/详情/统计同步；编辑→返回仍一致；删除→关联状态与恢复正确；AI失败→可重试且没有虚假结果。视觉微改不机械增加业务测试，但仍看受影响布局。

性能确认表记录会触发AI/长计算/大列表/大素材的字段与动作、触发频次、缓存/预计算替代、是否阻塞及待用户决定。没有测量时写“预估/待测”，不能输出假耗时或伪造成本。

报告包含：运行环境、页面与状态、截图/点击证据、发现并修复的问题、未验证限制。不能单凭主观8/10或零报错宣布高质量完成。
