# 内容驱动的设计方法

来源融合：huashu-design 的上下文/资产/四问、impeccable shape/product/brand，以及 design-taste-frontend 的模式与改版边界。

## 从任务进入

- 明确角色、使用频率、当前目标与使用环境。例如教师连续处理材料和学生临时查反馈，所需密度与导航不同。
- 分清业务产品与品牌展示：产品重稳定位置、可预测操作和连续任务；展示重主题、节奏与识别度。不是同一套首屏规则。
- 看已经存在的真源：页面、Figma、组件、PRD、token和素材；只问会改变主结构且无法从这些来源确定的缺口。
- 列出内容范围：空、典型、大量；标题/姓名/文件名的长短；图片缺失；AI长答案。不要先选版式再编文案填满。

## 页面四问

1. 这个页面在任务链路中起什么作用：进入、比较、处理、编辑、结果还是恢复？
2. 用户如何看与操作：手机手持、电脑密集操作或投屏展示？
3. 用户最先需要理解/执行什么，哪些是次要或低频项？
4. 实际内容放得下吗？先画简短结构/容量草图，确认分组与滚动，不凭字号硬挤。

## 设计方向

方向应具体到信息层级、导航方式、密度、字色距和资产角色。不要用“高级、现代、专业”代替决定。已有标准直接沿用；无标准时从适合任务的参考形成一套语言。品牌辨识度可以来自真实素材、节奏和恰当细节，不需要随机布局。

当用户要探索，或两个方向确实影响理解，制作少量差异明确的代表样例。差异应是构图/层级/密度/交互，而非只换主色。使用同一批真实内容才能比较。确认后的方向才推广；不能给每页换风格。

## 代表页到全站

先选最能暴露系统问题的页面，而非最漂亮的简单首页。典型页面校准基本组件，复杂页验证密集信息、长内容或浮层。截图后调整空间、字重、可读性、素材裁切和关键状态，才抽成公共组件；一次性布局保持局部。

改版先辨别体系内修补还是重构。保留型修改从问题最大的层级/间距/字体角色入手，不默认字体换新或加动效。需要改变导航、业务对象、字段或流程时同步PRD与来源，不能归入纯视觉修改。
