# 原型工作室

## 先判断这次任务

读取当前项目规则、用户最新需求、已有原型和受影响规格。用户明确指定的产品、范围、标准件、技术栈和已确认数据规则优先。已有项目保留其工作目录与构建方式；不为使用本包重建工程。资源路径均相对于本包根目录（本文件向上两级）；脚本用实际绝对路径执行，不把安装缓存路径写入项目。

按下表读取必要的专项 `SKILL.md`。这是按需加载说明，不是自动创建新任务或必须启动多个代理。

| 本次工作 | 应读专项 | 结束条件 |
| --- | --- | --- |
| 整理材料、规划页面、补充字段或业务流程 | [产品规格](../prototype-spec/SKILL.md) | 来源、范围、页面、数据与待确认项可追溯 |
| 新建或修改可操作原型 | [设计实现](../prototype-build/SKILL.md)，涉及业务变更再读产品规格 | 页面与相关规格同轮更新，操作可验证 |
| 比较视觉方向，暂不实现 | 设计实现的视觉探索模式 | 同业务范围的可比较方向；不自动进入建设 |
| 使用已指定标准件 | 设计实现＋[标准件索引](../../references/standards/index.md) | 锁定版本、结构、行为、图片按原件复用 |
| 提取、修改或升级标准件 | [标准件管理](../prototype-components/SKILL.md) | 完整依赖、状态、样例和版本可复用 |
| 检查或完成原型 | [原型验收](../prototype-qa/SKILL.md) | 有对应范围的静态、浏览器和设计证据 |
| 离线包、Word、Figma 或发布 | [原型交付](../prototype-delivery/SKILL.md) | 转换后的产物另行验证 |

## 变更链

1. 确定受影响页面、业务对象、状态与公共组件。纯视觉小改只校验内容未漂移，不重新规划产品或随机修改数据。
2. 在相应维护源落实授权变更：业务含义和决定归规格，记录归共享原型数据，锁定组件归标准包。只更新受影响部分。
3. 实现页面与交互；相关页面 PRD 同轮更新。代码可揭示差异，未经确认的代码行为不能自动变成需求。
4. 运行同步脚本生成导航与 PRD 阅读内容，再检查受影响页面和关联数据。没有修改规格的纯视觉变更也需检查阅读内容仍然新鲜。
5. 按请求交付，并明确已实现、已验证、待确认及未验证范围；不要把检查通过标成用户已评审。

## 不可省略的约束

- 业务页面采用同文档原生 DOM，公共导航与内容不得以 iframe 套壳；保留独立元素可选择性。第三方嵌入例外、旧入口迁移与插件验证见设计实现专项“页面承载与元素可选中性”。
- 每个业务页面及独立场景状态必须登记并有页面 PRD；可访问的页面列表 icon 与 PRD icon 每页都有。路由以路径、查询参数和 hash 区分。阅读工具在业务界面之外，不把 PRD 元数据混入产品文案。
- 按业务对象定义增删改查。派生数据、外部只读记录或固定项可无直接编辑入口，但必须有维护方、来源、规则和不能修改的理由。
- 新增无来源数据只询问相关问题，继续其他独立工作。不能自行批准模拟规则、数据库预置或高成本 AI 字段。已有确认规则在适用范围内复用，不重复询问。
- 已确认模拟数据保持关系与范围一致；统计从基础记录计算。默认模拟运行状态，不自建真实后端。
- 高成本数据使用同一份决策台账生成确认表。估算与实测分开，用户决定和依据保留。待确认项允许草稿推进，但不能宣布正式验收完成。
- 指定局部标准件只锁定指定区域。不可为了美化替换真实图片、删字段、加功能或给全部页面套用某一种营销/装饰风格。
- 视觉探索、生图、Figma 写入与部署按任务启用；外部动作遵循本轮授权与工具边界。官方插件的强制前置技能在实际调用工具前读取。

## 产物与完成标准

项目内保存页面清单、PRD、数据台账、确认记录和实际业务记录；本包只保存通用资源。新项目采用 [项目合同](../../references/contracts/project-contract.md)。已有项目可适配其维护源到该合同，避免同时维护两套规格。

正式完成前读原型验收；发现缺口就补齐或明确限制。脚本只能证明其检查项，无法自动证明视觉质量、语义正确或所有实际交互。
