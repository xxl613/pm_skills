# 原型视觉与交互实现

使原型有明确的视觉层级、稳定的组件语言、真实可操作的业务流程和可追溯内容。保真、设计感和操作完整性同等重要。

## 输入与工作方式

先读项目 `pages.json`、`data.json`、`decisions.json`、当前页面 PRD、`DESIGN.md` 及已有页面；按[项目合同](../../references/contracts/project-contract.md)保持字段兼容。不要因缺少另一个技能的 PRODUCT.md 重新初始化或阻断已有项目。

创建或变更业务规则时读取[产品规格](../prototype-spec/SKILL.md)，按其页面 PRD 版式同步字段、整体逻辑与状态机；直接调用本技能也执行这一要求。纯视觉小改只核对内容与规则没有变化。

判断任务属于哪种方式，已有明确证据时自主执行：

| 方式 | 执行依据 |
|---|---|
| 指定标准件 | 读取对应标准件参考、真实代码与素材；标准区域按契约复制，只改允许的业务槽位 |
| 既有体系内修改 | 先截图/读当前实现，保持项目字体、token、导航与组件语言，最小范围调整 |
| 参考复刻 | 以实际截图/Figma/页面为真源，逐项登记可见资产，结构和交互均核对，见[来源复刻](../../references/adapters/source-replica.md) |
| 自主新设计 | 由任务、角色、内容容量、端与品牌形成设计方向；见[设计方法](../../references/visual-craft/design-method.md) |
| 视觉探索 | 仅在用户要求或方向有实质歧义时做差异明确的样例；标准区域保持锁定，探索不自动成为全项目规范 |

若需要新增数据且查不到来源，立即把具体缺口问清楚；可继续不依赖该数据的设计工作。不能为了画面丰满发明统计值、业务状态、AI能力、品牌背书或服务承诺。

## 设计到实现

### 页面承载与元素可选中性

- 新建业务原型默认使用**当前文档中的原生 DOM**：公共导航、正文、按钮、卡片、弹窗和抽屉必须在同一个 `document` 中。多页用普通链接跳转，或用框架路由/组件直接渲染；静态 HTML 可用构建时模板组合。样式隔离用命名空间或局部样式，不用 iframe 隔离业务页面。
- 不以 iframe / frame / object / embed 套壳整个页面或主要业务区域；不把整页截图、Canvas 或闭合 Shadow DOM 当作可选中的界面。真实照片、插图、视频等媒体仍按正常资源使用。第三方服务确实只能嵌入时，先说明该局部区域的选择/导出限制，并取得用户确认；不能把这个例外扩展为全站壳层。
- 标准包默认只安装资源，选定 HTML/CSS/JS 后在宿主原生 DOM 中集成。`STANDARD-MOUNT` 的隔离 iframe 仅适用于用户明确要求的标准件演示/测试样例，不得用于交付业务页，即使标准示例本身使用 iframe。
- 改造已有 iframe 原型时，先清点入口、嵌套、参数与消息依赖，保留旧链接（可做兼容跳转）、场景参数、浏览器前进后退、滚动/固定区、PRD 与页面目录绑定。不能仅删 iframe 标签造成空白页，也不能为消除 iframe 擅自改写业务内容。
- 验证必须包含：页面正文属于顶层 `document`、主要业务区域无框架嵌套；导航/弹窗/刷新/深链可用；代表性文字、按钮与卡片可分别选中。若用户点名 Figma 或采集插件，在其浏览器实际尝试元素选择；没有实际操作证据就只报告 DOM 检查，不宣称插件兼容已通过。

涉及 Figma 输出时，读取[Figma交付适配](../../references/adapters/figma-delivery.md)，其中包含动态页面采集、可见性验证及临时采集代码清理要求。

### 页面制作流程

1. **任务与内容先行。** 确定首要动作、主要信息、分组关系、进入/返回路径，检查空、典型和大量内容。按对象与任务选列表、表格、详情、工作台、对话、流程、抽屉，不能把所有页面画成营销首屏或卡片网格。
2. **确定可复用的视觉语言。** 处理字阶、中文混排、内容宽度、间距、功能色、状态色、边界/阴影、图标和真实资产。记录在 `DESIGN.md` 并落实到 token；已有标准不重复选字体与配色。[排印](../../references/visual-craft/typography.md)、[布局](../../references/visual-craft/layout.md)、[颜色与素材](../../references/visual-craft/color-assets.md)按需读。
3. **代表页校准。** 新体系先完成能覆盖主要结构的代表页，检查真实截图和关键状态再批量推广。明确的小改动不必重新生成设计稿；来源充分的标准件不重复探索。规模较大时优先校准典型页与密集/复杂交互页。
4. **实现可操作流程。** 绑定共享数据而非每页复制数字。新增、修改、删除后所有受影响页面与派生统计同步。按钮、卡片、菜单和跳转都有实际结果；只读/不可用操作有业务原因，不能以无意义 toast 代替实现。见[交互与状态](../../references/visual-craft/interaction.md)。
5. **逐端适配。** 依据内容与任务调整导航、列、固定区、抽屉/底部弹层，不能把桌面缩小冒充移动。V5等指定标准的适配方式优先；通用设计见[跨端布局](../../references/visual-craft/responsive.md)。
6. **同步本轮变更。** 业务变更当轮更新页面 PRD、相关数据定义/来源/操作与页面登记，保留用户审核事实。脚本不能理解语义或自动批准需求。运行 `python3 scripts/sync/sync_review.py --project PROJECT --inject`，再用 `--check` 检查源与派生评审资料一致。每个登记页面有浮动页面目录和对应完整 PRD。
7. **可见验收。** 运行项目校验与[视觉验收](../../references/visual-craft/visual-review.md)，实际看图并点击主流程。自动检查通过不代表视觉正确；报告已运行的证据与未验证部分。发现可能高频调用AI、长任务或高负载字段，整理决策项交用户，不默默引入或删掉。

## 动效、风格与查询资源

- 动效表达状态、因果、空间关系或有意的叙事；不要求每页自动动画。优先[27项真实动效片段](../../assets/motion/README.md)，只复制对应片段，保留 reduced-motion、关闭清理与焦点管理。标准件已定动效不得覆盖。
- [风格库](../../references/styles/index.md)是可选构图/材质参考，不是额外全局禁令；同一项目不叠加几套互斥美学规则。
- 遇到具体UX/颜色/字体/图表/平台问题时运行 `python3 scripts/design/search.py "query" --domain ux --json` 或 `--stack react`。资料来自[本地查询库](../../references/visual-craft/catalogs/README.md)，输出是候选依据，不覆盖用户选择、来源事实或指定标准。
- 需要把视觉规范传给 Stitch 时读[Stitch适配](../../references/adapters/stitch.md)。不要因此创建第二套设计真源。

## 边界

不因设计任务自动新增后端、真实AI调用、生产发布或全站改版。图像生成可用于探索与图片资产，不替代可编辑界面、真实业务数据和交互说明。品牌完整VI与幻灯片/动画是独立任务，不强行装进业务原型。
