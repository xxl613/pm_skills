# 原型产品规格

本技能拥有页面登记、页面 PRD、数据语义与确认记录。它不选择独立视觉风格、不把普通产品强制转成对话流，也不以已画出的内容作为真实业务来源。

先读项目现有材料和 [项目合同](../../references/contracts/project-contract.md)。进入新项目时结合用户要求选择合适的文件目录；已有项目按当前布局接入，合同中的“项目根”是明确的原型范围，不是整个工作区。

仅规划页面或编写 PRD 时，先在现有页面清单和 PRD 中说明计划与已确认规则；不为通过运行检查创建空 HTML 或虚假的完整合同。制作可运行原型时再补齐对应入口、JSON 绑定和评审阅读视图；已有项目仍同步本轮受影响的登记内容。

## 按输入开展工作

- **材料尚未理清**：登记页面、角色和业务对象的出处，保留未知与冲突；不要为凑全貌发明功能。已有参数表须逐行承接或说明缺口。
- **准备创建原型**：把任务拆成业务页面与可直达状态场景，为每个登记入口绑定 PRD、数据对象和真实产品跳转。重要页面范围变化交用户确认；已授权范围内的小改动无需重新走完整建档。
- **调整已有原型**：先读当前 PRD、控制共享行为的代码与数据契约，明确改动影响哪些字段、状态与页面；同轮修改对应 PRD 和合同，再生成阅读视图。UI 中新增的业务规则不能静默升级为已确认需求。

页面 PRD 必须遵循[页面 PRD 版式规范](../../references/contracts/page-prd-format.md)，可复制[页面 PRD 模板](../../assets/templates/page-prd.md)和[空项目合同](../../assets/templates/spec-contracts/)。阅读版 PRD 使用页面名称、页面区域和日常业务表达，不展示页面 ID、研发字段名、对象路径或决定编号；内部 JSON 继续承担机器校验，不复制成第二份阅读内容。

每个用户可见的业务字段单独成表，固定写字段类型、页面上显示的文字、字段位置、数据来源逻辑、展示逻辑和操作逻辑。字段按页面从上到下、从左到右排列。不同角色的差异写进相关字段的展示和操作逻辑；数据从其他页面产生时，使用页面名称与页面位置说明。计算结果用文字说明计算方法，不能只引用内部字段。

跨字段、跨状态和跨页面的规则放入“页面整体逻辑”，每项逻辑单独成表。页面跳转写在相关操作结果中；AI、性能和未确认规则用完整语句写在相关字段或整体逻辑中，不单独建立章节，也不用内部编号代替问题。

每份页面 PRD 必须包含“页面状态机”，按版式规范使用状态说明和状态变更两张表，写清初始状态、触发动作、权限与判断条件、成功/失败/取消后的去向及跨页影响。以已确认规则为依据；尚未实现的已确认状态注明“已确认，待实现”，不能因为原型漏做而从 PRD 删除。合法终态或单一稳定状态不必虚构出口，互不依赖的流程分别说明。字段展示、整体处理步骤和状态流转相互对应，避免重复抄写；未知规则直接写完整问题。

## 数据必须可解释

内部合同逐项记录来源，并按业务对象记录增删改查的维护者、入口与结果；页面 PRD 则用用户看得懂的页面名称和操作结果表达。不是所有页面字段都应有四个操作按钮：计算值通过修改输入更新，外部数据通过外部系统维护，固定配置明确维护责任。不得把“没有前台入口”擅自解释为数据库写死。

发现新数据没有来源时，先查材料、对象字典和其他页面；仍不清楚就向用户提出具体问题：缺什么数据、出现在哪里、有哪些可行来源。记录 pending data-source 决策，暂停依赖这份答案的实现，继续不依赖它的工作。不得用看起来合理的样例值掩盖未知。

同一对象跨页共享稳定 ID 和同一组数据；总数、状态数量、进度与统计从记录推导。模拟业务数据只有在用户确认模拟规则后才能用于正式原型；`fixtureOnly` 只用于明确标注的技能自测样例，不能作为业务原型绕过确认的选项。

## AI 与性能取舍

对 AI 生成、重复计算、大文件、全量查询等评估触发点、频率、延迟/费用依据和替代方案；没有测量就写 unknown/estimated。AI 字段指向 performance 决策，高成本项用 `highCost: true`。

把高成本确认表在设计阶段给用户，交付时再次展示尚待决定的项目；不要等原型全部完成才第一次询问。用户回答后在同一决策记录写实际 answer/evidence，不能由脚本伪造确认。高成本 pending 允许探索草稿，阻止正式交付。

## 生成评审阅读视图

每个正式登记入口都有页面列表与页面 PRD 图标。原型修改后先同步人可读 PRD 和 JSON 真源，再运行：

```bash
python3 scripts/sync/sync_review.py --project /absolute/prototype --inject
python3 scripts/sync/sync_review.py --project /absolute/prototype --check --inject
```

命令以技能包根目录为工作目录。已有运行时接入时可省略 `--inject`；React/Vue 应消费相同生成数据和运行时入口，不复制另一份 PRD。脚本只生成全篇离线阅读数据和性能表，不能从任意代码改动自动理解业务并回写 PRD。

`implemented`、`verified`、`userReviewed` 是三份独立证据：实现完成、实际验证、用户评审。验证通过不得自动标记用户已评审；旧的评审在内容变化后需要重新核对。

完成时说明来源缺口、待确认、高成本决定和同步检查结果。对用户展示时使用完整问题和日常表达，内部编号只用于台账追踪。结构检查不证明业务语义自洽，交付还需验收能力检查真实跨页操作与计算。
