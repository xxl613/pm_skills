# 原型标准件

标准件是可复用的真实代码、交互行为与素材；references 解释选用和边界，assets 承载可复制结果。先读 [标准索引](../../references/standards/index.md)，只加载选中的标准；采用前读取其规范入口及对应交互/平台细则，不能只复制图片或外观代码。按 [包契约与工具](../../references/standards/package-contract.md) 登记和复用。

## 先锁定范围

- 读取用户指定页面/区域、现有项目标准绑定和版本。指定局部标准件只约束该区域及其必要依赖，不扩展成全站品牌、布局或行业规则。
- 已有标准直接消费；不重新描画已存在的图标/头像/插画。业务内容来自页面 PRD 与共享数据。新字段、新数据来源、CRUD 例外交还产品规格处理。
- 将某部分整理为标准件时，确认它的代码、样式、脚本、图片和状态是否已自包含。工具只登记选中的目录，不能自动理解并抽出任意 HTML；需要手工提取时先明确边界再整理依赖。

## 提炼与登记

1. 保留提取前源文件与哈希；建立最小独立样例，枚举结构、状态、交互和可变槽位。保留用户真实功能，不为“通用”加入新配置项。
2. 给标准件稳定 ID 和版本，登记实际来源、许可状态、平台、依赖、视觉基准。未知许可写 unknown，未经验证的 Figma 来源标为来源声明。
3. 使用 register_standard.py 登记到版本目录；同版本不覆盖。登记前和后都检查本地引用。规范说明放在包内 references 并纳入哈希，确保版本副本携带完整规则；根 references 只作索引。截图和交互验证另行执行，哈希检查不替代它们。
4. 在第二个页面消费同一版本，验证初态、操作后状态、空/错态中适用的部分，以及宿主样式不被污染。独立 iframe 样例仅用于标准件演示或测试；正式业务页按[设计实现专项](../prototype-build/SKILL.md)的原生 DOM 规则集成代码并记录差异，不能直接把隔离样例作为业务区域交付。

## 变更与升级

项目实例的业务修改留在项目。修改锁定结构、行为或素材意味着标准件变更：比较旧版与候选版，列出影响页面、兼容性、资源差异和迁移方法；用户请求只覆盖项目时不得上升为共享新默认。需要发布新版时使用新版本目录；旧项目固定原版本，只有明确的升级任务才切换。

每次报告分开列：来源保全、包校验、实际页面消费、浏览器交互、视觉比对。未执行的验证明确标记，不写“标准完全符合”。

V5 的细则与冲突处理见 [V5 标准](../../references/standards/v5.md)。旧 v5-ux-rule 不再作为第二套工作流调用。
