# 原型验收

读取受影响页面、页面 PRD、数据与决定台账，以及指定标准包。先界定本次验证范围；一个间距修改无需全产品重测，公共数据、导航或壳层修改需要覆盖关联页面。

如果本轮仅做规格评审，且原型尚未开始实现，检查 PRD 的来源、字段、权限、整体逻辑和状态机即可；不运行以 HTML 和项目 JSON 为前提的整项目检查，也不要求为检查创建占位文件。“已确认，待实现”在此阶段是后续工作，不是 PRD 不合格。进入原型交付验收后，再把缺失的实现与交互列为问题，并执行下面的运行检查。

## 确定性检查

包根下运行：

```sh
python3 scripts/check/check_project.py --project /absolute/project
```

它校验页面路由与 PRD、对象字段来源、派生引用、生命周期、确认记录、评审状态和生成内容新鲜度。返回报告里的错误先修复。尚有真实待确认项时可用 `--allow-pending` 继续草稿工作，报告仍列出待确认，不代表可正式交付。只有示例测试数据可以声明 `fixtureOnly`，不得用于跳过真实项目确认。

指定标准件还需运行 [标准件检查](../../references/standards/index.md) 中的校验命令。静态字段与哈希通过仅证明清单和文件一致，不能证明页面实际采用了正确结构与交互。

## 实际验收

- 页面 PRD：按[页面 PRD 版式规范](../../references/contracts/page-prd-format.md)核对。每个用户可见的业务字段有独立表格，包含字段类型、页面文字、位置、来源、展示和操作逻辑；计算方法用文字说清，来源使用页面名称和页面位置。页面整体逻辑逐项展示，阅读版不使用研发字段或内部编号代替业务说明。
- 页面状态机：先核对已确认规则是否完整，再对照实际操作，不能只检查已经实现的分支。检查首次进入和刷新时的状态选择、角色权限、成功/失败/取消/空数据及状态不变的情况。无法到达的状态或本应继续却无后续的流程要说明原因；合法终态、稳定只读状态不算缺陷。已确认但尚未实现的状态列为实现缺口，未经确认的代码行为不能直接写回正式规则。
- 原生 DOM：检查各登记入口及独立场景的主要内容位于顶层 document，没有 iframe/frame 或整页图片替代业务控件。旧链接、query/hash、前进后退、固定区和滚动、弹窗、页面目录及 PRD 绑定在改造后仍可用。点名采集插件时实际选择文字/按钮/卡片验证；静态无 iframe 只能证明结构，不等于插件抓取成功。用户确认的第三方嵌入例外须逐项记录。
- 页面：每个登记入口可达；路径、query 和 hash 对应正确 PRD；没有绑定时给出明确提示；浮层不挡主要操作，关闭、返回、键盘焦点和窄屏可用。
- 数据：同一对象跨页同值；总数、进度与状态由基础记录推导；来源能追溯到输入页面、外部资料、基础字段或明确的固定数据方式。
- 生命周期：实际新建、查询、修改、删除或解释只读例外；刷新及页面切换仍一致；取消无副作用；关联统计随记录变化。权限/错误/空态按本轮范围验证。
- 视觉：读取 [验收方法](../../references/visual-craft/qa.md)；检查主次层级、中文可读性、对齐、内容容量、图片、溢出、滚动与覆盖关系。参考复刻与原图在相同视口和状态对照。
- 性能：检查 AI 生成、多次请求、大数据列表及媒体等是否漏入成本评估；补充触发频率、等待体验、缓存/预计算替代方案。所有决定仍维护在 `decisions.json`，从它生成确认表，不开第二套来源。
- 证据：记录环境、页面状态、操作步骤、预期与实得。先确认 browser 工具可用，再执行；浏览器被权限或 URL 策略阻止时遵守工具边界，不换方式绕过拒绝。

## 结果状态

`implemented` 是实现情况，`verified` 是本次有证据验证的情况，`userReviewed` 只依据真实用户确认。不得因脚本通过、截图存在或 AI 自评而设置用户已评审。页面、业务规则有实质变化时使相关旧验证过期，保留历史用户评审证据并说明本次变更尚未评审。

输出包含：验证范围与方法、已通过项目、缺陷与影响、待确认项、未验证项。耗时数据明确标注估算或实测环境。未解决的关键来源、业务或高成本决定不能被省略成“全部通过”。

## 交付后的检查

离线包、Word、Figma 或发布由 [交付专项](../prototype-delivery/SKILL.md) 再验转换结果。源项目通过不能代替文件解压、离线页面、文字覆盖、可编辑性或实际访问证据。
