# V5 对话、输入和任务交互

代码真源是 `assets/examples/chat-flow-full.html`、`chat-flow-execution.html`、`chat-flow-plan-edit.html`；单件在 `assets/components/`。复制所选结构/图片再接业务事件，不从本文件重画样式。静态样例不证明下面的交互已接线。

## 输入台与发送

布局：文本/引用/附件区在上，动作行在下。左侧 `@` 引用上下文，`+` 添加资源/动作；右侧语音/通话/发送。发送最靠右、视觉优先。默认空态、输入态、附件态见 `input-composer.html`；最终发送钮的形状和真实图标以所选完整成品为准，不照抄旧文字里的方块草图。

| 动作/状态 | 必须行为 |
|---|---|
| 空输入 | 没有有效文字和可发送附件时禁用发送；纯空白不发送空消息 |
| `@` | 打开可搜索候选，按 Agent/文件/知识/人/任务等实际对象分组；图标+名称+一行说明，按需状态/权限；选中变可移除的引用 pill |
| `+` | 添加动作菜单，例如上传、工具、模板、能力；与“引用现有对象”的 @ 区分。只显示当前产品实际具备的动作 |
| 引用删除 | 只移除当前输入引用，不删除原对象；引用目标 id、可访问性、对象类型可追溯 |
| 候选键盘 | 上下移动候选，Enter 选中候选，Escape 收起；候选打开时 Enter 不越过菜单误发消息。选择后回输入焦点 |
| 发送 | 创建一条用户消息，按共享状态启动一轮任务；保存关联引用/文件；成功提交后清理当前草稿。失败保留可重试内容，避免重复创建 |
| 上传未就绪 | 由项目决定等待/禁用或允许其他已就绪内容发送；必须在 PRD 明确，不能显示失败附件却假报成功 |
| 生成中 | 显示真实任务状态与停止/暂停能力；是否支持同时发起下一轮必须在 PRD 定义，不能静默覆盖正在运行的任务 |
| 语音/通话 | 接入真实或明确登记的原型模拟行为；权限拒绝/不可用有反馈，不能空按钮或伪造正在通话 |

以下键盘规则是**本次补齐的实现默认**，旧规范和源样例没有完整键盘实现，不称作旧 Figma 实测：桌面 Enter 发送、Shift+Enter 换行；中文输入法 `isComposing`/composition 期间 Enter 只完成输入，不发送。移动软键盘按宿主设置处理，保留明确发送按钮。用户或现有产品另有约定时优先沿用，并记录到 PRD。按钮点击与键盘发送共用同一提交函数，防重复。

菜单不能遮挡正在编辑的文字；运行中 Agent/工具状态在输入台上方给出，不能只在旧正文里。全部真实新字段仍须来源、CRUD 和性能说明；使用“标准件默认”不能豁免数据确认。

## 生命周期与说话人

通常按 `用户请求 → 接收/判断 → 必要的派发 → 执行/生成 → 产物 → 完成/交还控制 → 可选追问 → 输入恢复`。单 Agent 任务不凭空加交接；主 Agent 负责组织与总结，子 Agent 只结束自己的阶段。

- 先产物、后完成；生成中标签不能和已完成产物永久同时停留。
- 一条消息一个说话人。头像和职能化名称固定，不附加冗长角色宣传副标题。所选角色 PNG 与办公室插画保持身份映射；不要每轮换人。
- 头像基线 36×36、圆角10；过程插画 178×112。已有项目头像优先，新增从包内 media/avatars 固定选取，不能把演示角色当业务授权。
- 派发/专员执行放白色圆角过程卡，细描边、圆角16；每个 Agent 段落可带对应办公室插画。主 Agent 最终回答是普通消息，没有过程卡壳或该过程插画。
- 完成后过程默认收起，可展开回看；`chat-flow-full.html` 是展开视觉态。展开/收起不得丢消息/任务数据。流式生成时较早过程段落弱化，最新段落正文色；完成后回看恢复正文色，不把历史段落做成不可读。
- 只显示用户能理解的接收、调用、派发、生成等状态，不暴露私有推理链、workflow 内部节点或原始系统日志。

## 消息头与拍了拍

头部顺序：头像 + 职能名称 `|` 可选时间 `|` 可选技能/状态。名称、时间、状态同用 14px、secondary 灰，不把名称加粗加深。分段用细竖线，闪电用真实 `msg-skill-bolt.svg`（16px）。产物到位后移除“进行中”或转简短完成态。

派发方用一条完整消息说明接收、判断、交给谁；消息正文的**最后一个子元素**接 `@派发方 拍了拍 @接收方 说，开场语`。两个 mention 是高30、圆角4、浅灰底、14px semibold 的 chip；派发方灰，接收方 success 绿；连接文字14px灰。外面不再套胶囊，不居中另起无头像消息。链式移交可由当前 Agent 发给下一个；只有真实需要该协作时出现。

## 完成操作与追问

顺序：产物 → 可选完成句 → 本轮唯一操作栏 → 可选追问。过程消息不重复挂栏。

| 元素 | 顺序与外观 | 行为 |
|---|---|---|
| 完成状态 pill | 第1；高38/圆角19/灰底、check图标 | 内容来自任务状态与规则，不需要每次让AI重新生成一句状态文案 |
| 播放文字 pill | 第2；同尺寸白底、voice-bars图标 | 播放本轮答案；播放/停止状态正确；不可用时明确反馈 |
| 复制、举报反馈、赞、踩 | 第3组；4个38圆图标按钮、18图标；踩使用对应图标/规范方向 | 复制真实答案；反馈绑定当前消息；赞踩互斥且可取消，不能只换色不保存状态 |
| 追问建议 | 每条完整问句、统一对话图标、浅底可点行；有内容时通常2–4条 | 点选成为新一轮用户输入；不是任务内部交接或关键业务确认 |
| 关闭追问 | 建议下方右对齐文字链接 | 仅隐藏本轮整组建议，不清对话，不隐藏操作栏 |

保留真实 `action-check/voice-bars/copy/report/like/dislike.svg` 等图片。建议是否生成、何时更新、是否缓存属于数据/性能决策；不强制每次动作调用 AI。

## 执行计划与并行

复制 `chat-flow-execution.html` 的四件套。只列实际参与的 Agent；所有计数、进度、耗时与状态来自同一任务数据。没有可估算进度就显示不定进度，不编造百分比/耗时。

| 部件 | 固定布局与状态 |
|---|---|
| 执行计划抽屉 | 右侧500；标题/关闭；灰底圆角16任务卡、48圆图标、任务名16 semibold、状态/耗时、6px进度条、暂停/终止；运行日志入口 |
| 运行日志时间线 | Agent头像30、名称14 semibold、用时、14/26描述、24高状态chip；完成正文色/执行品牌蓝/等待灰，虚线连接；并行组单独分组且成员分别说明状态 |
| 任务总数浮层 | 主对话左下、320宽白底描边圆角16浮层影；完成数/总数；每任务状态、名称、描述、负责Agent；执行行浅灰高亮 |
| 并行 Agent 胶囊 | 输入台上方；展开320×62、头像38、任务一句、暂停；收起126×62、头像/生成状态/进度弧 |

暂停保留可恢复状态；终止要说明影响并确认；完成/失败不继续跑假计时；编辑计划保留未提交草稿，保存后同步任务引用页面。并行局部完成用短状态行，细节留日志，最终由负责总结的 Agent 交还控制。

用户气泡 hover 可出现编辑/复制小条（白底圆角8、28按钮、16图标），键盘聚焦也可访问。编辑历史消息是否重算下游答案/清除分支是项目决策，不能只改原文却保留冲突结果。

## 桌面历史轨道

完整桌面 V5 对话选择时使用；仅选择输入台/卡片不附带全页轨道。复制 `assets/components/history-rail.html` 的结构、CSS、初始化器；独立可跑 `assets/standalone/history-rail.html`。移动不用。

- 定位 `.v5-main` 右缘垂直居中；抽屉打开时仍在抽屉左侧。轨道32×168，普通刻度24×3（源含26/28变化），当前32×3近黑。
- hover/focus/focus-within 展开300×244面板，右缘固定，padding8、圆角16、行高38，历史列表纵向滚动。
- 当前源样例固定16条，标题非空、title与文本一致、安全链接 `?conversation=01..16`。通过 URLSearchParams 接受01–16，缺失/非法回退01，同步唯一当前行/刻度/aria-current，不把query注入HTML。
- 轨道 tabindex0/历史 aria-label；行和轨道都有focus-visible。Escape 收起，焦点保留轨道且不滚动，离开后可再展开。
- 可见 `[aria-modal=true]`、`.v5-overlay`、`.v5-modal-mask` 存在时用原观察器隐藏轨道，轨道及16链接退出Tab；关闭恢复。列表本身不是模态。
- 不同时加入顶部历史按钮/常驻历史栏/旧minimap作为重复入口。16是组件容量样例，业务记录数/分页/真实会话路由由项目规格定义；改容量须同步刻度、链接、脚本、键盘和测试，登记为变体。

## 文件上传七态

输入/上传管理态的每张文件卡有文件名、类型、规模（大小/页数/时长）、状态、操作；图片用缩略图，文档用真实类型图标。长文件名截断保留扩展名。具体代码 `file-upload.html`：对话中横排上传卡270×70、图标36、hover删除、可滚动；其他消息卡随列宽，桌面典型320–420。

| 状态 | 展示 | 操作/迁移 |
|---|---|---|
| 已选择 | 输入台附件区，类型+名称+规模+待发 | 删除只移除草稿；开始上传进入上传中 |
| 上传中 | 同卡原位进度与状态 | 可取消；失败保留原因；禁用/等待发送遵照项目规则 |
| 上传完/解析中 | 同卡解析状态与轻进度 | 删除/等待；不提前声明内容已可用 |
| 已解析 | 就绪可引用 | 删除/发送；发送绑定文件id与当前消息 |
| 失败 | 同卡警告与原因 | 重试/移除；不默认模态打断 |
| 已发送 | 用户气泡下方精简独立文件卡 | 只保留文件名，不带上传管理态的大小/解析状态；查看/复制 |
| 已引用 | Agent结果中来源页/章/时间/片段标记 | 可查看原来源；不能伪造页码或不存在片段 |

文字气泡与文件卡分别有各自边界，外包右对齐的纵向组、组内约6px；整组参与主消息列大间距。既不塞进同一个气泡，也不散成远隔的 thread 项。多个文件各自保留上传状态；文件生成结果和用户上传来源不能混淆。

上传/解析是否真实、大小/类型限制、存储、删除范围、刷新保留与生成成本都需项目明确。示例动画不证明真上传或真解析。

## 高影响操作与文案

删除、终止和清除记忆须明确对象/范围，取消无副作用。清除记忆分清当前对话、任务、文件引用、Agent记忆、全局记忆；默认不删除可见聊天记录，除非用户明确选择。确认主操作用结果动词，次左主右；危险项区别于取消。

加载/错误/空态给用户下一步，尊重 reduced motion。文案描述当前对象、动作、影响，保持产品术语一致；不把PRD说明、路由名、演示导览或夸张营销带进业务界面。评审工具可独立标记供评审使用，不能伪装产品功能。
