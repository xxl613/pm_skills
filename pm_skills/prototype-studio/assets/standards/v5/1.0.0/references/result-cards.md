# V5 对话结果卡与内容排布

结构真源 `assets/components/chat-result-card.html`；对话 `.v5-rcard` 与表单 `.v5-card` 分开。当前内容的业务事实、状态来源和操作由项目规格决定。

## 选择载体

| 内容 | 使用方式 |
|---|---|
| 确认、过渡、短说明 | 普通文本，一个块一个对话动作 |
| 连续解释、报告、复盘 | 文档式正文/章节，不能把每一段装一张卡 |
| 单个对象/任务/资源/方案 | 一卡一对象，一个核心说明，少量关键字段，最多一个主操作 |
| 多个对象共享动作 | 组级CTA，不给每张卡重复同一动作 |
| 多条同构记录/不定条数 | 普通列表/表格、独立页面/抽屉；不要固定高度卡内滚动 |
| 多字段编辑/筛选/发布 | 项目选择的编辑层/页面，不能把复杂表单塞进结果卡 |
| 趋势/结构/比例等图表 | 先给结论，图与解释同列；数据有来源口径；简单事实不为装饰画图 |

结果卡 `max-width:600px; align-self:flex-start`，不强撑约800px消息正文列；移动随可用宽度收缩。长正文保持自然全宽。多卡纵向排或合理横向滚动；允许一个任务返回多个必要对象，不保留旧“问题数≈卡片数”机械限制。

长列表可用前3–5条+真实总数+查看全部，完整内容在列表/抽屉；少到一屏放下可直接列出。卡本身随内容长高，不设内部滚动条。多属性推荐项用 `.v5-reco` 的独立标题和标签行，白底surface，不能拼成“名称·属性·属性”一行。强调徽章用实心底白字，弱提示如适配度用浅底；不同语义不复用同一个徽章类。任何适配度/推荐级别都必须在数据合同有来源。

支持/陪伴式回答保持自然段落，避免把人当成诊断表格；真正需快速找到的紧急联络等安全信息可单独卡片呈现，不混在普通安慰内容中。

## 两种合法结构

选择其一，不能在同一张卡混搭：

1. 任务/方案/问题/提醒：类别 `.v5-rcard__label` → 标题 `__t` + meta → 内容块/选项/正文 → 底部 `__acts`。槽位可省略，出现顺序不变；标签永远在标题上方、操作最后。
2. 数据 key/value 卡：保留源中 `__hd` / `__bd` / `__foot`，用于字段、来源脚注。旧检查表一概禁止 `__hd` 不再有效。

| 层级 | 源类名 | 固定字号/行高 |
|---|---|---|
| 大标题 | `.v5-rcard__t` | 18/26 semibold |
| 描述 | `.v5-rcard__desc` | 14/20 secondary |
| 内容标题 | `.v5-block__n` | 16/24 semibold |
| 内容正文 | `.v5-block__d` | 14/24 secondary |

可以纯展示、带操作，或采用无色条的 `--plain` 内容块；突出选中块用 `--active` 绿浅底/边框。这种内容块选中与问题选项的品牌蓝 `--sel` 是不同组件状态，不应混为同一选择样式。

## 外壳生命周期四色

渐变统一135deg、左上色调约14–16%混白到65%位置回白；原代码为准，不改成随机平涂。卡内内容块白底，类别/状态文字同时表达含义。

| 颜色/类 | 意义 | 配套状态 |
|---|---|---|
| 默认灰白 `.v5-rcard` | 列表/选择/创建前预填/已结束 | 已结束用灰 `--done` |
| 黄 `--pending` | 创建后待开始/等待确认 | 黄 `--todo`，类别同色系 |
| 绿 `--success` | 创建成功/已发布 | 绿 `--ok` |
| 红 `--alert` | 警告提醒这一类型 | 提醒类别文字，不因内容“严重”就随意染红 |

这是生命周期/类型编码，不是情绪。普通卡中的风险通过明确文字、重点字段、卡内警示表达，不能全卡任意变红。同一状态跨页同色。表单/校验/Toast 可用其各自语义色，不把它们的四色规则搬到对话结果外壳。

## 槽位细节

- 类别是实际概念，如AI生成/专家协作/问题/提醒；默认灰，expert橙、alert红、ok绿。右上可有头像组/状态chip，用 `__toprow`；不发明装饰类别。
- `.v5-block` 左3px色条编码实际类型/层级，须配文字；块内标题、右meta、一行说明。不要无意义每块随机一种颜色。
- `.v5-opt` 为问题选项，全宽白底描边，选中 `--sel` 品牌蓝边/字；自由输入不能在正式交互原型里只画placeholder，必须是真实可输入控件并与选项互斥/组合规则一致。
- `.v5-rcard__acts` 左meta、右操作，纯按钮用 `--end`。主操作唯一近黑胶囊 `--primary`，次操作白描边 `--secondary`，次左主右。预计耗时等meta需有估计依据，不能照抄源样例秒数。
- 问题卡默认“跳过+完成”语义；业务明确拒绝/确认时用业务词，未选择是否可完成按PRD。点选、完成、跳过都要有状态迁移与校验。
- 状态 `.v5-status`：todo待开始/待确认、doing进行、ok发布/完成、done中性结束；既有 doing 为success浅底，执行日志的“运行中”则用品牌蓝，语义范围不同不得全局搜索替换。
- 日期记录行使用 `.v5-reco__row` + `__date` + `__main`，右侧状态/操作；它仍是列表项，不能用来给长列表套固定滚动卡。

修改操作后，同对象在所有卡片/详情/统计中一致更新；取消/校验失败不写入数据。派生字段默认只读，不为满足CRUD造人工编辑按钮。新形态先看现有任务/方案、协作、简报、问题、提醒形态是否合适，确需扩展则更新规范、代码、状态例和版本。
