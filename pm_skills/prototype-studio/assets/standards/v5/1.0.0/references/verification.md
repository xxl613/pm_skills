## 明确解决的冲突

- 00/02限制所有列表/详情只能进卡或抽屉，与05允许完整列表页、09长搜索整页冲突：按内容长度和业务需求选整页，不限信息架构。
- 旧一页一态禁止JS切换，与真实交互需求冲突：交互必须可运行，重要状态另给可直达URL或测试路径。
- 旧00/01/02手机状态区44，与当前tokens/09为59冲突：采用59，宿主用hosted隐藏演示区。
- 99说接收方mention品牌色，05与成品绿色：采用success绿色，不做全局品牌换色。
- 99禁止所有`__hd`，07明确两种合法结构：同卡不混搭，两种均可用。
- 99以“提问次数≈卡片数”限制多卡，05允许多必要对象和组级CTA：按任务与信息载体判断，不人为卡数配额。
- 原静态代码不覆盖全部行为，尤其移动搜索/反馈/确认/关闭：明确需要项目接线，不以“代码优先”吞掉交互规则。
- 普通结果卡扁平与四色渐变不是冲突；渐变编码生命周期，阴影仅浮层。卡内按钮近黑、页面CTA品牌蓝；不同语义范围勿混写。

## 每次采用标准的最小验收

| 层级 | 必须证据 | 不代表什么 |
|---|---|---|
| 包完整 | `check_standard.py --pack` 哈希、本地静态资源引用通过 | 不证明JS拼接动态资源或所有按钮可用 |
| 消费绑定 | 项目锁定id/version/entry/scope；可检查iframe的真实src或人工核对DOM接入 | 复制包不代表目标页面已用它 |
| 规则对照 | 明确选了哪些组件/状态；按对应规范检查结构、颜色、交互、移动承载 | 源样例自身不能充当规范合格结论 |
| 浏览器 | 实际路径、输入/点击/返回/提交/失败、控制台和动态图片；HTTP与目标离线file模式 | 静态check或截图不能证明业务CRUD |
| 数据/PRD | 每个字段来源、共享状态、CRUD/只读原因、生成策略和成本；新增缺口询问用户 | 标准样例数字不是用户事实/批准 |
| 视觉 | 指定范围截图、基准来源和有限差异；手机键盘/安全区、桌面抽屉/历史/输入台互不遮挡 | 没有新Figma时不可称最新Figma一致 |

完整对话接入须验证：空/非空/附件发送、IME不误发、@选择与移除、上传失败重试、过程折叠、停止/恢复/终止、卡片选择/保存、复制与反馈、关闭追问、历史query/Escape/模态遮断。只选某件时只验该件实际能力，不要求增加无关流程。
