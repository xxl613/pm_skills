# 页面名称

## 一、页面说明

用一段日常语言说明页面给谁使用、解决什么问题、用户通常从哪个页面进入，以及在这里能完成哪些主要事情。不写页面 ID、代码路径或研发字段名。

## 二、页面字段逻辑

按页面上从上到下、从左到右的顺序，为每个用户可见的业务字段建立一张独立表格。这里的“字段”指页面上的名称、时间、状态、数字、列表等业务内容，不是数据库字段。

### 字段：字段名称

| 说明项 | 具体内容 |
|---|---|
| 字段类型 | Label / Status Tag / Input / Textarea / Combobox / Select / Radio Group / Checkbox / Switch / Date Picker / Date Time Picker / Upload / Button / Link / List / Table / Card / Progress Bar / Chart / Avatar/Image / Rich Text；允许按实际界面组合 |
| 页面上显示的文字 | 写用户实际看到的标题、内容格式、空状态和错误提示；原型示例数据明确说明是演示内容 |
| 字段位置 | 使用页面区域和相对位置描述，不使用组件名、选择器或代码路径 |
| 数据来源逻辑 | 优先写明来自哪个页面的哪个位置、由谁通过什么操作产生；计算结果用文字写清计算方法；外部系统或后台配置写清来源和维护方 |
| 展示逻辑 | 写明显示条件、格式、空状态、异常状态和不同角色看到的差异 |
| 操作逻辑 | 写明谁能操作、操作条件、成功/失败/取消结果，以及对其他页面的影响；只读内容直接说明不能操作及原因 |

继续按上述格式填写页面上的其他字段。没有明确来源或规则时，在对应单元格直接写出需要用户回答的完整问题，不使用内部编号代替问题。

## 三、页面整体逻辑

无法只归入某个字段的跨字段、跨状态或跨页面逻辑逐项展示，每项单独成表，不写成连续的大段说明。

### 逻辑：逻辑名称

| 说明项 | 具体内容 |
|---|---|
| 触发时机 | 写清什么时候执行这项逻辑 |
| 涉及内容 | 使用页面上的业务名称列出受影响内容 |
| 处理逻辑 | 用日常语言分步骤说明系统怎样处理 |
| 页面结果 | 写清处理后用户在当前页面看到什么 |
| 对其他页面的影响 | 使用页面名称说明哪些页面同步变化；没有影响时明确写“无” |

## 四、页面状态机

状态机说明页面会处于哪些状态，以及用户操作、数据变化或系统结果会怎样推动状态变化。状态名称使用用户能理解的业务说法，不使用代码枚举、页面 ID 或内部编号。字段自己的显示、隐藏、禁用等规则仍写在对应字段的“展示逻辑”中；这里记录会改变页面整体内容或主要操作方式的状态。

### 状态说明

| 状态名称 | 进入条件 | 页面表现 | 可进行的操作 | 离开条件 |
|---|---|---|---|---|
| 状态名称 | 写清页面为什么进入这个状态，包括首次打开或重新进入时的选择条件 | 写清用户此时能看到什么 | 写清谁可以进行哪些主要操作 | 写清什么情况会结束这个状态；流程终态可写“流程到此结束”，稳定只读状态可写“本页无后续变更” |

按已确认规则列出其他状态。新页面先写清规则再实现；已确认但尚未实现的状态注明“已确认，待实现”。首次打开、刷新或重新进入时，说明如何根据当前数据选定或恢复状态。

### 状态变更

| 当前状态 | 触发动作或事件 | 判断条件 | 变更后状态 | 页面变化 | 对其他页面的影响 |
|---|---|---|---|---|---|
| 当前状态名称 | 写清谁做了什么，还是数据或系统结果发生了变化 | 写清所需权限和业务条件；没有额外条件时写“无” | 写清进入哪个状态；状态不变时也要明确写出 | 写清当前页面的内容和操作发生什么变化 | 使用页面名称说明哪些页面同步变化；没有影响时写“无” |

状态变更应覆盖已确认规则中适用的成功、失败、取消和数据为空等分支。只有一个稳定状态时，说明没有状态变更，不为填表编造操作。业务阶段与弹窗开关等状态若能同时存在，按不同流程分别列两张表，不枚举所有组合。复杂处理可引用本页对应的整体逻辑名称。需要用户决定时，直接写出完整问题；不能把未经确认的实现行为写成正式规则。
